# 1. PROJECT OVERVIEW

## Product Name

Nourish

## Tagline

Your wellness journey, beautifully organized.

## Product Category

Wellness Consultation and Appointment Management Platform.

## Target Users

Two types of users:

**Client:** An everyday person booking consultations with a nutritionist.

**Nutritionist:** A wellness professional managing consultations, appointment statuses, and client attendance.

## Primary Problem

A nutritionist manages appointments through WhatsApp and Excel.

Approximately 25% of clients fail to attend scheduled consultations.

The nutritionist only discovers their absence after waiting for them.

The current workflow creates:

- Wasted consultation slots.
- Lost revenue opportunities.
- Manual scheduling work.
- Double-booking risks.
- Poor visibility into upcoming attendance.
- Difficulty tracking appointments.
- Inconsistent client communication.

## Product Solution

Develop a beautifully designed appointment-booking platform where clients can book, reschedule, cancel, and confirm consultations.

The nutritionist should be able to manage appointments through a connected dashboard.

Both interfaces must use the same database.

The application should provide appointment confirmation functionality to help reduce no-shows.

The experience should be simple enough for a nontechnical user.

## Database Requirements

Use:

- UUID primary keys.
- Foreign keys.
- Appropriate indexes.
- Database constraints.
- Transaction management.
- Alembic migrations.

### Prevent Double Booking

Do not rely only on frontend validation.

Enforce availability at the database level.

For fixed-duration slots, use an appropriate uniqueness strategy for active appointments.

For variable-duration appointments, use PostgreSQL exclusion constraints or equivalent transaction-safe overlap protection.

A cancelled appointment must release its slot.

The database must prevent simultaneous requests from reserving the same slot.

Return HTTP 409 Conflict when a slot is already taken.
